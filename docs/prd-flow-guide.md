# PRD · 客服流程分步引导（功能 3）

## 目标
让不熟悉的客服员工按「分步卡片」照做，每步说明**要操作什么**，并附截图（可圈选高亮区域）。降低培训成本、减少操作遗漏。

## 方案选择：混合（网页步骤卡 + 图片附件），不做独立图片编辑器
- **不推荐纯图片方案**：需自建 canvas 标注编辑器（箭头/框/序号/文字），工作量大，且产出只能给人看、不能被程序消费。
- **推荐混合**：每步 = 结构化卡片 `{ 标题, 操作说明, 截图(可圈选高亮框), 可选自动执行动作 }`。
  - "图片"部分 = 上传截图 + 拖一个高亮框（轻量 SVG/canvas overlay，零门槛），解决"有的操作不需要网页、纯图片怎么编辑"——截图上圈一下即可。
  - "网页"部分 = 结构化步骤，新人逐步照做；步骤可挂后续 RPA 动作（v1 仅占位）。

## 关键设计变更（用户优化：支持多方案，而非单一）
- **「方案」是顶层多实例单元**：不再是"一个流程"。用户可建多个方案（退款处理 / 发货跟进 / 投诉处理…），顶部方案切换条切换，**互不影响**。
- 每个方案内部仍是步骤列表（原混合步骤卡设计不变）。
- 支持**复制方案**（基于现有方案快速派生新方案再改），降低重复录入。

## 数据模型
```
Scheme {                       // 顶层"方案"
  id: string
  name: string                 // 方案名（必填）
  desc?: string
  tag?: string                 // 分类标签（如 售后/物流）
  updatedAt: string
  steps: Step[]
}
Step {
  id: string
  title: string        // 步骤标题
  desc: string         // 操作说明（必填）
  image?: string       // 截图 dataURL（可选）
  rect?: { x:number; y:number; w:number; h:number } // 圈选高亮区域(相对原图比例 0~1)
  action?: { type: string; payload?: unknown }      // v1 占位，不接执行
}
```
存储：`zustand persist` → `localStorage('autoplay.flows')`（数组，每个元素是一个 Scheme）。

## 用户流程（用户优化：多方案浏览器，避免 20 个方案难找）
1. **方案浏览器**（列表页）：顶部「搜索框 + 分类筛选」（按名称/标签过滤），下方**卡片网格**展示方案（名称 + 分类标签 + 步数 + 最近编辑 + 打开/复制/删除）。20+ 方案时靠搜索/筛选收敛，不再用横向条。
2. 点「打开」进入某方案的**编辑/阅读区**：左步骤列表（当前方案内）+ 右步骤表单（标题 / 说明 / 上传截图 / 在截图上拖高亮框 / 删除步骤 / 上移下移）。
3. 阅读视图：分步卡片 + 「上一步 / 下一步」+ 进度条；圈选框叠加在截图上高亮；顶部标明当前方案名。
4. 导入/导出（复用 `frontend-file-io-tdd` 模式）：方案 JSON 可整体导出分享、导入覆盖（或追加为新方案）。

## 验收标准
- [ ] 方案浏览器：搜索（名称/标签）+ 分类筛选可用，网格展示，多方案不卡。
- [ ] 多方案 CRUD（新建/打开/复制/删除），方案间互不干扰。
- [ ] 步骤 CRUD（增删/上下移），仅在当前方案内生效。
- [ ] 每步可上传截图；图上可拖拽出一个高亮矩形（保存为比例坐标，缩放不失真）。
- [ ] 阅读视图逐步推进，进度可见，圈选框正确叠加；顶部标明当前方案名。
- [ ] 导出/导入方案 JSON（序列化纯函数单测 + DOM 仅 tsc）。
- [ ] 持久化、空状态友好（无方案时引导新建）。
