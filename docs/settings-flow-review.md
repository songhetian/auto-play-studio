# 设置流程评估与改进方案

> 评审对象：控制台 + 实例窗口的配置/设置链路
> 评审口径：专业桌面工具（配置可预期、错误可定位、状态不丢失）
> 本轮状态：**问题 1–9 已修复并验证**；建议 A–G 为后续排期项

---

## 一、现状：设置分成两层，但边界没被说清楚

| 层级 | 位置 | 存哪里 | 影响范围 |
| --- | --- | --- | --- |
| 全局设置 | 控制台（原为「无」，本轮新建 `/settings`） | 前端 localStorage | 整个应用 |
| 实例配置 | 每个实例独立窗口 `/instance/:id/config` | 引擎 SQLite（`instances.config_json`） | 仅该实例 |

**问题 0（结构性）**：改造前**根本没有全局设置入口**。主题、引擎地址、数据目录这些"全局偏好"散落在页脚文字与代码常量里，用户无处可改。本轮补上了 `/settings`，并把两类设置的边界写成明确规则：

- **能改全局的，都在左侧「设置」**：外观主题、引擎连通性、数据目录、快捷键。
- **只影响单个实例的，都在实例窗口里**：列映射、执行策略、绑定窗口、监控规则、流程编排。
- 判据：**一项配置是否可能"这个实例要、那个实例不要"** —— 会，就放实例层。

---

## 二、改造前的具体问题

### 阻断级：改了不生效（用户会以为软件坏了）

配置页有 9 处输入是"死的"——用 `defaultValue` 渲染、`onChange` 是空函数，输入框能打字但值从不写回配置，点保存也没用。

| 位置 | 控件 | 症状 |
| --- | --- | --- |
| 列映射 | 客户名称列 / 消息内容列 / 状态列 | 能输入，保存后重新打开恢复原值 |
| 统一发送内容 | 开关 + 文本域 | 开关点不动，文本存不下 |
| 执行策略 | 起始行 / 结束行 / 失败重试 / 失败后 | 改行区间无效，仍然跑默认范围 |
| 执行策略 | 跳过已成功行 / 回写失败原因 / 执行前备份 | 三个开关全部无响应 |
| 绑定窗口 | 目标窗口下拉 | 选了不生效，实例跑起来仍绑旧窗口 |

**根因**：UI 层把"展示当前配置"和"编辑配置"用了两套写法 —— 一部分字段走 `patchConfig` 受控更新（monitor / logi / 指令），另一部分偷懒用了非受控 `defaultValue`。**同类控件在同一页里两种行为**，是最容易失去信任的缺陷类型。

**修复**：全部改为受控（`value` + `onChange` → `patchConfig`），并补上字段级校验与脏标记。新增 `configValidation.ts` 的 `zodFieldErrors()` 把 Zod 校验结果摊平成"字段路径 → 错误文案"，一处校验、两处使用（字段旁提示 + 保存按钮可用性）。

### 严重级：UI 展示了不存在的能力

| 问题 | 说明 | 处理 |
| --- | --- | --- |
| 两个假开关 | 「运行时置顶」「失焦自动激活」在 `rpaConfigSchema` 里**没有对应字段**，也无引擎实现 | 移除；能力真做出来再加 UI |
| 列映射名不副实 | 文案写"下拉项取自 Excel 表头"，实际是自由文本输入；写错列名不报错，要到运行才失败 | 改为真下拉，选项来自上传后探测的表头 |
| 物流缺关键选择器 | `logi.colWaybill`（物流单号列）是**必填**，但整个 UI 没有选择入口，实例永远配不完整 | 补齐下拉，与列映射同一套组件 |
| 输出文件名假装可编辑 | 「输出文件」是输入框但 schema 无 `outFile` 字段，改了什么也不会发生 | 改为只读预览，标注"文件名由原文件派生" |

**原则**：**UI 上能编辑的每一项，背后必须有真实字段与真实消费方**。展示不存在的能力比缺少功能更伤——用户会反复尝试并最终不信任这个页面。

### 体验级：错误与状态不可见

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 保存失败只有一句 `保存失败` | 不知道错在哪个字段，只能逐个猜 | 字段级红字提示 + 顶部「还差 N 项：A、B、C」 |
| 保存按钮永远可点 | 必填未填时点了才报错 | 有错误即禁用，`title` 说明原因 |
| 没有"改了没存"的标记 | 关闭窗口后丢失，用户不自知 | 头部「未保存」标签；保存按钮文案随状态变「保存配置 / 已保存」 |
| 无保存快捷键 | 桌面工具肌肉记忆缺失 | `Ctrl/Cmd + S` 保存 |
| 监控区域让用户手写字符串 | 要记住 `full` 或 `x,y,w,h`（物理像素），写错静默按整屏处理 | 改「整屏 / 自定义区域」分段控件 + X/Y/宽/高数值框 + 框选回填 |
| 运行详情页「← 返回」是死键 | 实例在独立窗口里打开，`history.back()` 无历史可退 | 移除，改由「配置」按钮做双向跳转 |

**原则**：**配置页的三种状态必须一眼可辨** —— 有错（哪里错）、有改动（存没存）、正常。缺任何一种，用户就只能靠"点了没反应"来猜。

## 三、目标流程（改造后）

```
左侧「设置」 —— 全局偏好
  外观（浅色 / 深色 / 跟随系统，即时生效并记住）
  引擎（连通状态、端口、重新检测）
  数据（数据目录、打开目录、定位）
  快捷键（F9 / F10 / Ctrl+S / /）

实例窗口「实例配置」 —— 单实例
  编辑 → 即时写入本地 store（脏标记亮起）
       → 字段级校验实时反馈
       → Ctrl+S / 「保存配置」→ PUT 到引擎（脏标记熄灭）
       → 有错误则按钮禁用 + 顶部列出待补项
```

未保存的编辑只存在于内存 store，点保存才落引擎 —— 这样"半填状态"不会污染数据库，代价是需要用户显式保存。

## 五、建议但本轮未做（按优先级）

| 优先级 | 项 | 说明 | 需要先定的口径 |
| --- | --- | --- | --- |
| 高 | **自动保存** | 编辑 debounce 800ms 后自动 `PUT`，头部显示「已保存 12:01」。当前漏点保存就丢工作 | 是否允许"草稿态"落库（引擎 `PUT /config` 不做校验，技术上无害） |
| 高 | **关闭前未保存提醒** | 需在主进程 `win.on('close')` 拦截并弹原生对话框（要新增 IPC） | 拦截还是自动保存后再关 |
| 中 | 配置跨实例复制 | 现在只能整实例 clone；常见诉求是"把这套指令复制到另一个实例" | 复制哪些段（流程/策略/映射） |
| 中 | 全局默认值 | 把默认重试次数、默认相似度阈值提到设置页，新实例继承 | 必须是**引擎侧**全局配置，不能只存 localStorage，否则多机不一致 |
| 中 | 流程编排离线校验 | 指令缺参数、逻辑冲突只在运行时暴露；应给"检查"按钮列出问题 | 校验规则清单 |
| 低 | 列映射相似度提示 | 列名与表头高度相似时提示"你是不是想选 X"，减少手误 | 阈值 |
| 低 | 设置项搜索 | 设置条目继续增长后需要（导航搜索的同类能力） | — |

### 一条架构约束（写进约定）

**影响执行的配置一律落引擎 SQLite；纯前端偏好才落 localStorage。**
主题属于后者（无需求一致性），引擎地址/端口属于前者（若可改也须落库）。当前唯一写 localStorage 的全局配置是主题，符合该约束。
