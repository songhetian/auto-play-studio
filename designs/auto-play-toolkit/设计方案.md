# AutoPlay Studio — 整体设计方案

> 原型：`页面设计 v3.html`（**最新版，Arco Design 风格**）· 早期版本 `页面设计 v2.html`
> 技术栈：Electron + React + React Router + React Query + Zustand + Zod + ECharts

## 0-A. v4：架构方向修正 —— 控制台（Launcher）+ 独立实例

**问题**：v1–v3 把全部能力塞进「一个软件的一个窗口」，无法满足"同时操作多个软件"的真实场景。

**新架构：每个工具都是一个独立软件，可多开并行**

```
AutoPlay 控制台（唯一常驻窗口）
├─ 工具箱：列出所有工具 → 点「新建实例」打开一个独立实例窗口
├─ 实例管理：所有实例的状态 / 进度 / 绑定目标 / 运行控制（置顶、复制、停止、关闭）
├─ 共享服务：图像库（跨实例共享资产）、引擎与全局设置
└─ 实例窗口（可多开，彼此完全独立）
   ├─ 自动化脚本助手 · 实例 A1 → 绑定「客户管理系统」
   ├─ 自动化脚本助手 · 实例 A2 → 绑定「企业微信」     ← 同时执行，互不阻塞
   └─ 桌面图片监控 · 实例 M1 → 全屏监测，命中即报警
```

**隔离与共享边界**
| 维度 | 隔离（每实例独立） | 共享（全局） |
|---|---|---|
| 窗口绑定、方案/指令、Excel 数据源 | ✅ | |
| 运行状态、进度、日志、热键焦点 | ✅ | |
| Worker 进程、崩溃与恢复 | ✅ | |
| 图像库资产、全局设置、引擎连接 | | ✅ |

**工程要点**
- 前端：每个实例 = 独立 Electron `BrowserWindow`（或独立路由实例 + 独立 Zustand store 命名空间），控制台只做实例注册表与生命周期管理
- 后端：每个实例独占一个 Python worker 进程，实例互不阻塞；异常退出不影响其它实例并保留现场
- 生命周期：新建实例 → 配置 → 运行 → 最小化到托盘 → 关闭自动保存；下次启动可恢复上次实例
- 复制实例：复制配置但执行上下文独立（可快速"多开"同一套流程到不同窗口）

### v5 交互修正与新增工具

**交互修正**
- **配置页只做配置**：移除运行控制（开始/暂停/停止），保留「数据与配置 / 流程编排」两个 Tab，运行统一入口为「前往运行详情 →」
- **指令库改版**：从密集按钮改为列表条目（类型色点 + 名称 + 右侧「添加」hover 反馈），按分组排列
- **指令拖拽排序**：画布节点 `draggable`，dragstart / dragover / drop 完成顺序调整，插入位置有蓝色指示线
- **实例桌面 → 运行详情**：点击窗口标题或「运行详情」进入该实例运行详情页（KPI + 进度 + ECharts + 明细 + 日志）

**物流查询：不依赖接口的实现路径（Provider 可切换）**

| 方式 | 原理 | 优点 | 限制 | 适用 |
|---|---|---|---|---|
| ① Excel 匹配合并（默认） | 平台后台导出含物流状态的表 → 按单号 VLOOKUP 合并 | 纯本地、零外部依赖、万行秒级、不受改版/风控影响 | 需先导出对照表 | 首选，量大 |
| ② 网页自动化查询 | 复用本工具箱 RPA 引擎：打开查询页 → 输入单号 → 读取结果 | 无需申请接口/密钥 | 页面改版需更新流程；验证码与风控；每单 2–5s | 量小、无对照表 |
| ③ 接口查询（预留） | 快递100 / 顺丰 / 京东官方 API | 稳定、快 | 需密钥与费用 | 后续接入 |

**抓哪一页 / 怎么抓内容（网页自动化方式的落地细节）**

- 目标选择：❌ 百度聚合框（iframe 跨域、结构常变）→ ✅ 快递100 网页版（通用）与各快递官网（最准）；最优仍是平台后台导出
- 抓取方式优先级：
  1. **DOM 选择器提取**（推荐）：Playwright/内嵌 Chromium → 输入单号 → 点击 → `wait_for_selector` → `inner_text()` → 解析结构化；比 OpenCV 找图稳定得多
  2. **页面内部接口复现**：DevTools Network 找到 XHR，复现 URL/参数/headers 取 JSON（无需申请密钥，但仍有签名与频控风险）
  3. **截图 + OCR**：仅在强反爬时兜底，慢且准确率不稳
- **站点适配器配置化**：每个站点保存 `{url, 单号输入框, 查询按钮, 结果容器, 状态字段, 轨迹字段}`，页面改版只改配置不改代码；配套「选择器录制器」点页面元素生成选择器
- **稳定性保障**：运行前自动跑一次测试单号自检，失败即告警；保存 HTML 快照便于改版复盘
- **限速与合规**：每单间隔 ≥1.5s + 随机抖动、真实 UA、遇验证码暂停转人工、仅查自有单号、遵守目标站点服务条款

- 统一接口 `LogisticsProvider`：`ExcelMatchProvider` / `WebAutomationProvider` / `ApiProvider`，输出字段一致（物流公司、状态、签收时间、最新轨迹）
- 单号结果落本地 SQLite 缓存，避免重复查询；未命中标记「无轨迹」，支持人工补录
- 合规提示：网页方式请控制频率并仅查询自有单号，遵守目标站点服务条款

**新增工具：物流信息查询（可多开）**
- 拖拽上传 Excel → 自动检测所有列 → 点击选择「物流单号」列 → 按单号查询物流信息
- 输出：**写入新文件**（原文件名_物流信息.xlsx），原文件保持只读；新增列：物流公司 / 物流状态 / 签收时间 / 最新轨迹
- 运行详情用 ECharts 展示：结果分布（已签收/运输中/已揽收/无轨迹/待查询）、快递公司分布、查询耗时趋势

**Excel 统一交互**
- 所有 Excel 入口使用同一拖拽上传组件（`.dz`）：支持拖拽落盘与点击选择，`.xlsx / .xls / .csv`，上传后自动识别列名与行数

### 实例配置页（每个实例独立，入口：侧栏「实例配置」/ 实例操作「配置」）

一个实例 = 一套独立配置，三个 Tab：
1. **窗口与数据**：绑定窗口（仅影响本实例）、数据源与列映射（客户名称列=搜索关键词 / 消息内容列 / 状态列可选自动创建）、统一发送内容（开启后忽略消息内容列）、执行策略（范围、重试、失败后、跳过成功行、回写失败原因、备份）、数据预览（成功/失败/跳过/待执行 + 重跑失败行 / 重置状态）
2. **流程编排**：指令库 → 画布 → 属性面板（图像类可重新截图 / 换图 / 调阈值），配置属于当前实例
3. **运行监控**：本实例的运行控制、进度、成功/失败/跳过/待执行、日志（独立保留）

## 0-B. 稳定性评审：当前尚未稳定，最小稳定清单

| 级别 | 问题 | 处理 |
|---|---|---|
| P0 | 实例状态机不完整（缺 completed / error / stopping、暂停恢复、异常恢复） | 定义显式状态机与合法迁移，禁止非法跳转 |
| P0 | 配置与执行耦合，实例间通信仅靠共享数组 | 配置只改数据，执行器只消费数据；经 IPC 同步到控制台 |
| P0 | 结果回写与跳过成功行未落到实例模型 | 已补入配置页执行策略与数据预览 |
| P0 | 无持久化，关闭/崩溃即丢失现场 | 实例配置与进度定时落盘，启动可恢复 |
| P1 | 每 tick 全量重绘桌面窗口 | 已改为局部更新（进度/时长/计数） |
| P1 | 运行中关闭实例无确认 | 已加二次确认 |
| P1 | 复制实例未复制配置 | 已深拷贝 cfg |
| P1 | 并行上限无排队/限流；F9/F10 无"焦点实例"概念 | 引入实例焦点与执行队列 |
| P1 | 日志无上限、无落盘与审计 | 环形缓冲 + 文件落盘 + 操作审计 |
| P2 | 无安全护栏（执行前确认、发送频率限制、敏感操作二次确认） | 加入风控与速率限制 |

## 0-C. v3 设计语言与工作台内部布局（沿用 Arco，作用于单个实例内部）

**视觉：全面对齐 Arco Design**
- 主色 `#165DFF`（Arco blue-6），中性底 `#F7F8FA`，描边 `#E5E6EB`，文字层级 `#1D2129 / #4E5969 / #86909C`
- 语义色：成功 `#00B42A`、失败 `#F53F3F`、提醒 `#FF7D00`（仅用于小圆点与文字，不做大面积背景）
- 控件 4px 圆角、卡片 6px；表头浅灰底；hover/focus 用 `0 0 0 2px rgb(22 93 255/.12)` 蓝环
- **取消一切彩色大色块背景**（避免"黄底"观感），状态一律用白底卡片 + 彩色数字/图标/标签表达

**信息架构：从工具升级为专业软件**
- 顶部：Electron 标题栏 + 头部（**方案 Tabs** / 方案管理 / 保存 / 运行 / 设置）
- 左侧 196px 模块导航；底部新增**状态栏**（运行状态、当前方案、指令数、保存状态、引擎连接、热键提示）
- 工作台保留四步向导，但第 3 步改为 **IDE 式三栏**：指令库 | 流程画布 | 属性面板 + 底部面板（变量/数据预览/日志）

**新增：多方案切换与保存**（重点需求）
- 头部方案 Tab：可同时打开多个方案，Tab 上有"未保存"圆点，× 关闭时校验未保存修改
- 「方案管理」弹窗：新建 / 打开 / 复制 / 导出 JSON / 删除，列表展示绑定窗口、数据源、指令数、最近保存时间
- 保存与自动保存：保存后写入时间戳，状态栏与头部同步；任何修改置 dirty

**重做：流程编排**
- 工具条：单步执行 / 从此运行 / 断点 / 撤销 / 重做 / 查找指令 / 套用推荐流程
- 画布：卡片式节点（序号、类型色标、参数摘要、断点红点、启用开关、拖拽把手），点选即编辑
- 属性面板：按指令类型渲染表单（图像类可就地重新截图/从库替换/测试匹配/调阈值）
- 底部面板：变量表（{客户名称} 等）、数据预览、日志，可折叠

## 1. 本次改版要解决的四个问题

| 原问题 | v2 解法 |
|---|---|
| 新手要手动填窗口标题、手动逐条加指令，门槛高 | 工作台改为**四步向导**：① 选择窗口 ② 数据配置 ③ 流程编排 ④ 运行监控；第 1 步提供**进程/窗口选择器**，第 3 步提供**一键套用推荐流程** |
| 找不到窗口 | Electron 主进程枚举本机进程与窗口（IPC），列表化展示进程名/PID/窗口数/前后台，点选即回填，运行期自动激活置顶 |
| 图片/阈值改起来不方便 | 图像库升级为**统一资产层**：选中即编辑（重新截图/替换文件/改阈值/改标签），面板显示"被哪些指令与监控规则引用"，保存后**同步到全部引用**；指令参数里也能就地改图与阈值 |
| Excel 结果没有沉淀 | 行级状态回写：成功=成功、失败=失败+原因；下次执行**自动跳过成功行**，并提供"重跑失败行 / 重置状态" |

## 2. 页面结构

```
Electron 窗口（自定义标题栏）
└ 侧边栏：自动化工作台 / 图像库 / 桌面监控 / 数据统计 / 设置 / + 新工具（扩展位）
   └ 工作台 = 四步向导
      ① 选择窗口：进程选择器 + 已选窗口卡片（缩略图、自动激活/置顶、匹配方式）
      ② 数据配置：数据源 + 列映射 + 统一发送内容 + 执行策略 + 数据预览（状态徽章）
      ③ 流程编排：指令库（含一键模板） / 指令序列 / 参数编辑面板
      ④ 运行监控：运行控制 + 进度 + 结果分布环图 + 每行耗时折线 + 日志终端
```

## 3. 关键业务规则（已落实在原型中）

**列语义**
- 客户名称列（必选）＝**搜索关键词**，逐行填入搜索框
- 消息内容列（可选）＝每行发送内容；**启用统一发送内容后忽略此列**，全部使用统一文本
- 状态列（可选）＝不指定时程序**自动创建「执行状态」列**

**执行结果回写**
- 成功 → 写入「成功」；失败 → 写入「失败」+ 失败原因
- 执行策略：跳过已成功行（默认开）、失败重试 N 次、失败后继续/暂停、执行前备份 Excel
- 数据预览与运行监控页实时展示 成功/失败/跳过/待执行 计数，支持一键"重跑失败行"

**指令与图像**
- 指令分类：窗口 / 键盘 / 鼠标 / 图像判定 / 流程控制
- 键盘指令支持可视化组合键（Ctrl+Shift+Alt+Win + 常用键/F1–F12/字母数字）
- 图像指令参数：就地重新截图、从库替换、测试匹配、阈值滑块、超时、点击偏移、未命中策略

## 4. 技术栈分工

| 层 | 选型 | 职责 |
|---|---|---|
| 桌面壳 | Electron | 窗口枚举（IPC）、截图、全局热键 F9/F10、系统通知、文件对话框 |
| 路由 | React Router v6 | 模块级路由；工作台内四步用子路由 `/workbench/:step` |
| 数据请求 | React Query | 进程列表轮询（5s）、任务状态/日志轮询、图像库 CRUD、统计接口 |
| 状态 | Zustand | 编排 store（指令序列/选中项）、方案 store、UI store（步骤、弹窗） |
| 校验 | Zod | 列映射表单、指令参数 schema、IPC 消息与后端响应校验 |
| 图表 | ECharts | 结果分布环图、每行耗时折线、7 日趋势、成功率仪表、失败原因条形、时段负载 |
| 自动化内核 | Python（可选 FastAPI） | pyautogui/OpenCV 执行、Excel 读写回写、监控轮询与报警 |

## 5. 可扩展架构（后续加工具）

- 侧边栏由 **模块注册表** 驱动：新工具 = 写一个页面组件 + 在注册表加一行（含图标/路由/权限/懒加载）
- 后端对齐：`tools/<tool_id>/` 包实现统一 `ToolBackend` 接口，前端注册表与后端一一对应
- 共享能力复用：图像库资产层、任务运行器、日志/事件流、通知、设置
